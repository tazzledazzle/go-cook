# CI/CD Pipeline Design Spec

**Date:** 2026-07-11
**Status:** Approved

---

## Overview

A GitHub Actions CI pipeline for the `learn-you-a-torrent` BitTorrent client in Go. The pipeline enforces correctness on every push and PR, blocks merges on failures, and provides an on-demand analysis trigger for the code analysis subagent suite.

This spec describes the pipeline structure. The actual `.github/workflows/ci.yml` and `.golangci.yml` files are produced by the `/design-cicd` subagent (defined in the Code Analysis Subagents spec) after it reads the three analysis reports.

---

## Triggers

```yaml
on:
  push:
    branches: ["**"]
  pull_request:
    branches: [main]
  workflow_dispatch:   # manual trigger for on-demand analysis
```

---

## Stages

```
lint → test → race-detect → build → [analyze: manual only]
```

All four mandatory stages run sequentially. Each blocks the next on failure.

### Stage 1: `lint`

**Blocks merge:** Yes

**Commands:**
```bash
go vet ./...
golangci-lint run ./...
```

**Why first:** Catches format and correctness issues before spending time on test runs. Fast fail.

**Go version:** Pinned to `1.26.2` (matches `go.mod`).

---

### Stage 2: `test`

**Blocks merge:** Yes

**Command:**
```bash
go test ./...
```

**Scope:** All packages including UAT tests under `internal/uat/`. The `testdata/minimal.torrent` fixture drives `TestDownloader_downloadsMinimalTorrent` — no network required.

---

### Stage 3: `race-detect`

**Blocks merge:** Yes

**Command:**
```bash
go test -race ./...
```

**Why separate from test:** The race detector adds significant overhead; keeping it separate makes the `test` stage fast and lets failures be attributed clearly. Priority elevated if the anti-patterns report flags goroutine concerns.

---

### Stage 4: `build`

**Blocks merge:** Yes

**Command:**
```bash
go build ./cmd/torrent
```

**Purpose:** Confirms the binary compiles cleanly even when all tests pass (e.g., catches import cycle issues or missing main package wiring).

---

### Stage 5: `analyze` (on-demand)

**Blocks merge:** No — manual trigger only (`workflow_dispatch`)

**What it runs:** The `/gsd-analyze` orchestrator skill (requires Claude Code CLI in the runner). Writes reports to `docs/analysis/` and commits them.

**When to run:** Before releasing a milestone, after major refactors, or when explicitly requested.

---

## Key Design Decisions

| Decision | Rationale |
|---|---|
| Sequential stages | Simple dependency chain; failure attribution is unambiguous |
| `golangci-lint` in CI | Consistent with local `analyze-syntax` agent; config checked into `.golangci.yml` |
| No coverage gate | This is a learning project — coverage thresholds add friction without benefit at this stage |
| No Docker | The binary has no runtime dependencies beyond Go stdlib; containerization adds no value here |
| No deploy stage | No deployment target exists for v1; pipeline is CI-only |
| Go version pinned | Prevents accidental language upgrades breaking the build |

## Files to Create

| File | Purpose |
|---|---|
| `.github/workflows/ci.yml` | GitHub Actions pipeline definition |
| `.golangci.yml` | Linter configuration (which linters, exclusions, thresholds) |

Both files are generated by the `/design-cicd` agent as part of `docs/analysis/CICD-DESIGN.md`, then extracted and committed to the repo root.

---

## Branch Protection (recommended, manual setup)

Once the pipeline is green on `main`:
1. Enable **Require status checks to pass** for: `lint`, `test`, `race-detect`, `build`
2. Enable **Require branches to be up to date before merging**
3. Do NOT require the `analyze` stage (it's manual)

Address any HIGH-severity findings from the analysis reports before enabling protection — failing lint in CI with unresolved high-severity issues creates friction for every PR.

## Prerequisites

- GitHub repository with Actions enabled (already on `tschumacher/bit-torrent` branch pattern)
- `golangci-lint` available to runners (use `golangci-lint/golangci-lint-action@v6` GitHub Action)
- Go `1.22` available on runner (use `actions/setup-go@v5`)
