# kquick CLI Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Build a read-only `kquick` CLI for listing, describing, and reading logs from Kubernetes Pods.

**Architecture:** Add a Cobra executable under `design-kube/cmd/kquick` and keep its command logic in `design-kube/internal/kquick`. A small runtime interface isolates typed `client-go` operations from formatting and makes every command testable without a cluster.

**Tech Stack:** Go 1.24, Cobra, Kubernetes `client-go`, typed CoreV1 APIs, `sigs.k8s.io/yaml`, table-driven tests.

---

Use @golang-pro and @test-driven-development while implementing this plan. Run
all commands from `design-kube` unless a step says otherwise.

**Step 3: Define the runtime boundary**

In `runtime.go`, define only operations needed by version one:

```go
type Runtime interface {
	ListPods(context.Context, string) (*corev1.PodList, error)
	GetPod(context.Context, string, string) (*corev1.Pod, error)
	ListPodEvents(context.Context, string, string) (*corev1.EventList, error)
	StreamPodLogs(context.Context, string, string, *corev1.PodLogOptions) (io.ReadCloser, error)
}
```

Implement `ClientGoFactory.New` with:

- `clientcmd.NewDefaultClientConfigLoadingRules()`
- `ExplicitPath` when `--kubeconfig` is set
- `clientcmd.ConfigOverrides.CurrentContext`
- `clientcmd.ConfigOverrides.Context.Namespace`
- `clientcmd.NewNonInteractiveDeferredLoadingClientConfig`
- `ClientConfig()` and `Namespace()`
- `kubernetes.NewForConfig`

Wrap the typed client in `clientGoRuntime`. Implement Pod list/get, Pod Event
selection, and log streaming with contextual `%w` errors. Event selection must
match the Pod name, namespace, and kind.

**Step 4: Implement the root command**

Expose:

`cmd/kquick/main.go` must use `signal.NotifyContext` for `os.Interrupt` and
`syscall.SIGTERM`, call `ExecuteContext`, print one concise error, and return

### Task 4: Implement `kquick logs pod`

**Files:**
- Create: `design-kube/internal/kquick/logs.go`
- Create: `design-kube/internal/kquick/logs_test.go`
- Modify: `design-kube/internal/kquick/root.go`

**Step 1: Write failing log tests**

Use readers that record closure and a context-aware blocking reader. Cover:

- `logs pod NAME` and plural alias.
- Missing/excess arguments and unsupported resources.
- A single container without `--container`.
- A selected container using `-c` and `--container`.
- A multi-container Pod without a selection returns valid names.
- An unknown selected container returns valid names.
- `--follow` reaches `PodLogOptions.Follow`.
- `--tail 25` reaches `PodLogOptions.TailLines`.
- Values below `-1` are rejected before API access.
- Stream bytes are copied exactly to stdout.
- Get, stream-open, copy, and close errors are surfaced.
- Cancellation terminates a blocked stream.

Run:

```bash
go test ./internal/kquick -run TestPodLogs -v
```

Expected: FAIL because `newLogsCommand` does not exist.

**Step 2: Implement local validation**

Add helpers that:

- Return regular container names in declaration order.
- Auto-select the only container.
- Require `--container` when more than one regular container exists.
- Reject an unknown selection and list valid names.
- Reject `--tail < -1`.

Version one intentionally excludes init and ephemeral container log selection.

**Step 3: Implement streaming**

Create `newLogsCommand(app *App) *cobra.Command` with:

- `Use: "logs RESOURCE NAME"`
- `-c/--container`
- `-f/--follow`
- `--tail` with default `-1`

Fetch the Pod first for container validation. Then call:

```go
runtime.StreamPodLogs(ctx, namespace, podName, &corev1.PodLogOptions{
	Container: selectedContainer,
	Follow:    follow,
	TailLines: &tail,
})
```

Always close the stream. Copy to the configured stdout with `io.Copy`. Preserve
copy and close failures; if both occur, return the copy failure and include the
close failure in the message.

**Step 4: Run focused tests**

Run:

Expected: PASS.
